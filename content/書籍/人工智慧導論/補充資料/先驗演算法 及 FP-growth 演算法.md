## 一、 先驗演算法 (Apriori Algorithm)
先驗演算法是關聯規則探勘的==開山之作==，其核心在於利用「先驗性質」來==剪枝，減少搜尋空間==。

### 1. 定義與邏輯
- **核心思想**：**向下封閉性（Downward-closure property）**。若一個項目集（Itemset）是頻繁的，則它的所有子集也必須是頻繁的；反之，若一個項目集是非頻繁的，則它的所有超集（Superset）也必然是非頻繁的。
- **適用場景**：超市購物籃分析（Market Basket Analysis）、早期推薦系統、交易資料庫規模適中且項目重複率高的場景。
- **具體步驟**：
	1. **掃描資料庫**：計算所有單一項目（1-項目集）的支持度，篩選出大於等於最小支持度（min_support）的頻繁 1-項目集，記為 $L_1$。
	2. **連接步驟（Join）**：將 $L_{k-1}$ 與自身進行連接，產生候選 $k$-項目集 $C_k$。
	3. **剪枝步驟（Prune）**：檢查 $C_k$ 中每個候選項目集，若其存在任何一個長度為 $k-1$ 的子集不屬於 $L_{k-1}$，則將該候選項目集直接刪除。
	4. **支持度計算**：再次掃描資料庫，計算 $C_k$ 中剩餘候選集的支持度，篩選出頻繁 $k$-項目集 $L_k$。
	5. **迭代**：重複步驟 2 至 4，直到無法產生新的頻繁項目集。

### 2. 時間複雜度
- **最差情況**：$O(2^d \cdot |D|)$。當最小支持度設為 0 時，演算法必須產生並計算所有可能的項目組合（$D$ 為項目總數，$|D|$ 為交易筆數）。
- **平均/最佳情況**：取決於最小支持度與資料稀疏度。若最小支持度高，大量候選集在早期被剪枝，時間複雜度約為 $O(\sum_{k=1}^{w} |C_k| \cdot |D|)$（$w$ 為最大頻繁項目集的長度）。

### 3. 空間複雜度
- **最差情況**：$O(2^d)$。在迭代到中間階段（通常是 $C_2$ 或 $C_3$）時，候選項目集的數量會達到峰值，可能撐爆記憶體。

### 4. 正確性證明
- 設項目集 $A \subseteq B$。根據支持度（Support）的定義：
  $$Support(A) = \dfrac{\text{包含 } A \text{ 的交易筆數}}{|D|}$$
  因為任何包含 $B$ 的交易必然也包含 $A$，所以包含 $B$ 的交易集合是包含 $A$ 的交易集合的子集。
  因此，必然有 $Support(A) \ge Support(B)$。
  若 $A$ 是非頻繁的（即 $Support(A) < min\_support$），則 $Support(B) \le Support(A) < min\_support$，故 $B$ 必然也是非頻繁的。此單調性（Monotonicity）保證了剪枝過程絕不會漏掉任何頻繁項目集。

### 5. 邊界條件
- **空資料庫**：直接返回空集合。
- **最小支持度 = 1.0**：僅返回在所有交易中皆出現的項目。
- **最小支持度 = 0.0**：產生所有可能的項目組合，導致記憶體溢出（OOM）。
- **單筆交易包含極多項目**：在連接步驟會產生爆炸性的候選集。

### 6. 優缺點與替代方案
- **優點**：邏輯簡單直觀，易於實作與平行化。
- **缺點**：==必須多次完整掃描資料庫==（每次迭代 $k$ 都要掃描一次），且會產生極為龐大的候選項目集，I/O 與記憶體開銷巨大。
- **替代方案**：FP-growth 演算法、ECLAT 演算法（採用垂直資料格式）。

### 7. 實作細節
- **資料結構**：通常使用 **雜湊樹（Hash Tree）** 或 **字典樹（Trie）** 來儲存候選項目集，以加速支持度的計數與比對。
- **效能陷阱**：避免在每次計算支持度時都使用巢狀迴圈遍歷整個資料庫，應建立倒置索引（Inverted Index）或對交易進行過濾。

## 二、 FP-growth 演算法 (Frequent Pattern Growth)
為了克服 Apriori 演算法需要多次掃描資料庫與產生龐大候選集的致命缺點，韓家煒（Jiawei Han）等人提出了 FP-growth 演算法。

### 1. 定義與邏輯
- **核心思想**：**不產生候選集**。透過將資料庫壓縮儲存至一棵 **頻繁模式樹（FP-tree）** 中，然後將挖掘任務拆解為多個條件資料庫（Conditional Databases），採用分治法（Divide-and-Conquer）遞迴挖掘。
- **適用場景**：大型資料庫、資料密集且項目關聯性強的場景。
- **具體步驟**：
	1. **第一次掃描資料庫**：找出所有頻繁 1-項目，並依支持度由大到小排序。
	2. **建構 FP-tree（第二次掃描資料庫）**：對於每筆交易，過濾掉非頻繁項目，並按照排序後的順序插入 FP-tree 中。若有共同前綴則共享節點，並增加節點計數。同時維護一個「項頭表（Header Table）」，用指標鏈結相同項目的節點。
	3. **遞迴挖掘 FP-tree**：從項頭表最底部的項目開始，沿著指標找出其所有「前綴路徑」，建構該項目的「條件模式基底（Conditional Pattern Base）」。接著以此建構「條件 FP-tree」，並遞迴挖掘，直到條件樹只剩一條路徑或為空。

### 2. 時間複雜度
- **最差情況**：$O(2^d)$。當所有交易的項目完全沒有交集時，FP-tree 無法壓縮資料，遞迴挖掘的複雜度仍會退化。
- **平均/最佳情況**：$O(|D|)$。建構樹僅需掃描資料庫 2 次。在資料高度關聯時，FP-tree 壓縮率極高，挖掘速度比 Apriori 快數個數量級。

### 3. 空間複雜度
- **最差情況**：$O(|D| \cdot d)$。當資料極度稀疏、無任何共享前綴時，樹的節點數會非常龐大，加上指標的額外開銷，記憶體佔用可能超越原始資料庫。
- **最佳情況**：$O(d)$。當所有交易完全相同時，整棵樹只會有一條單一路徑。

### 4. 正確性證明
- FP-tree 完整保留了原始交易資料庫中所有頻繁項目的共現資訊。
- 根據分治法，任何包含項目 $x$ 的頻繁模式，必然是由 $x$ 與 $x$ 的前綴路徑中的頻繁項目組合而成。
- 透過項頭表的鏈結，演算法能無遺漏地遍歷所有包含 $x$ 的路徑。因此，將問題限縮在 $x$ 的條件模式基底中進行遞迴求解，在數學上與在全域資料庫中求解是完全等價且互斥的。

### 5. 邊界條件
- **無任何頻繁項目**：FP-tree 僅含根節點（Root），演算法立即結束。
- **極度稀疏的超大型資料**：FP-tree 節點指針過多，可能導致記憶體不足。

### 6. 優缺點與替代方案
- **優點**：**只需掃描資料庫 2 次**，不產生任何候選集，執行速度極快。
- **缺點**：FP-tree 的結構複雜，不易進行分散式與平行化運算；當資料庫極大且稀疏時，整棵樹無法完全放入記憶體。
- **替代方案**：H-Mine 演算法（基於超鏈結的無樹挖掘）、Apriori。

### 7. 實作細節
- **資料結構**：多叉樹結構（每個節點包含項目名稱、計數、父節點指標、子節點指標、同名節點鏈結指標）與項頭表（陣列或雜湊表）。
- **效能陷阱**：遞迴呼叫過深可能導致系統棧溢出（Stack Overflow）。在 Python 或 Java 中，過多的節點物件會帶來巨大的垃圾回收（GC）壓力，實作時常需使用陣列來模擬指標以優化記憶體。

## 三、 先驗演算法 與 FP-growth 比較表

| 比較項目 | 先驗演算法 (Apriori) | FP-growth 演算法 |
| --- | --- | --- |
| **核心技術** | 候選集產生與剪枝 | 頻繁模式樹 (FP-tree) 與分治法 |
| **資料庫掃描次數** | $k$ 次（$k$ 為最大頻繁項目集長度） | 固定 2 次 |
| **記憶體佔用** | 候選集數量龐大時極高 | 樹結構與指標開銷，稀疏資料時較高 |
| **執行速度** | 較慢（受限於 I/O 與候選集比對） | 極快（記憶體內運算） |
| **實作難度** | 簡單 | 複雜 |

## 四、 其他常見的資料探勘演算法
除了上述兩種關聯規則演算法外，在資料探勘（如您在 [[07 知識發現#7-1 知識發現流程|7-1 知識發現流程]] 中所見的分類、聚類等任務）中，還有以下重要演算法：
1. ECLAT 演算法 (Equivalence Class Transformation)
	- **領域**：關聯規則探勘。
	- **特點**：採用**垂直資料格式**（即 `項目 -> 交易 ID 集合`）。它不需要掃描資料庫，而是透過計算交易 ID 集合的==交集（Intersection）來快速得到支持度，非常適合深度優先搜尋。==
2. K-Means 演算法 (K-平均演算法)
	- **領域**：聚類（Clustering，非監督式學習）。
	- **特點**：如 [[01 AI 不過就是問個好問題：認識 AI#K-平均演算法|K-平均演算法]] 所述，透過反覆計算群集重心並重新分配樣本點，將資料劃分為 $K$ 個群集。
3. DBSCAN 演算法 (Density-Based Spatial Clustering of Applications with Noise)
	- **領域**：聚類（Clustering）。
	- **特點**：基於密度的聚類演算法。它不需要事先指定群集數量 $K$，能識別任意形狀的群集，並能有效過濾雜訊（離群點）。
4. 決策樹演算法 (如 C4.5, CART)
	- **領域**：分類（Classification，監督式學習）。
	- **特點**：如 [[07 知識發現#決策樹|決策樹]] 所述，利用資訊獲利（Information Gain）或吉尼係數（Gini Index）來選擇分裂特徵，建構出易於人類理解的規則樹。
